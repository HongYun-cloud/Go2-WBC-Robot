## 编译错误修复方案

已完整检查 `msg/Go2Telemetry.msg`、`include/ros2/go2_control_node.hpp`、`src/ros2/go2_control_node.cpp`、`CMakeLists.txt`、`package.xml`，存在两类问题：

### 问题 1：`fillTelemetryMessage` 字段名与消息定义不匹配（编译错误）

消息文件字段已全部小写化（`p_ref_fl_x`、`a_ref_*`、`contact_fl` 等），但 `src/ros2/go2_control_node.cpp:436-515` 的实现仍在引用旧的大写字段名（`p_ref_FL_x`、`a_des_FL_x`、`contact_FL`），生成的 C++ 头文件中不存在这些名字，必然编译失败。且循环体对 4 条腿都只写 FL 字段（`legN` 数组声明了但没用）。

**修复**（重写 `fillTelemetryMessage` 函数体 + 节尾调用处）：
- 用成员指针表 `static const double Go2Telemetry::* field[12] = {...}` 按组建立 [leg×3+axis] → 消息字段的映射（p_ref/p_act/v_ref/v_act/a_ref/a_act/f_mpc/f_wbc 共 8 组），循环内 `telemetry_msg_.*field[i] = ...` 一次填齐 96 个足端字段，4 条腿各写各的字段
- `a_des` 参数对应消息里的 `a_ref_*` 字段；`a_act_*` 取成员变量 `a_foot_act`（数值微分，已有）
- contact 四条腿分别写 `contact_fl/fr/rl/rr`；body_* 字段不变
- 删掉节尾调用处的节流块（`count % 10` + 未使用的 `double t`），改为 500Hz 直接调用（纯内存拷贝，锁内 ~106 个 double 写，与 50Hz publishState 竞争可忽略；单线程 executor 下读成员 `v` 安全）
- 清掉残留的 "PlotJuggler UDP" 段落注释

### 问题 2：`em.BUFFERED_OPT` Python 报错（构建环境问题，非代码问题）

之前所有失败构建都复用了旧 `build/` 里缓存的 CMakeCache，其中 `Python3_EXECUTABLE` 指向 conda 的 Python 3.8（`~/miniconda3/envs/rl_env/bin/python3`）。该环境的 em 是 4.x，删除了 `BUFFERED_OPT` 常量；而 ROS Humble 的 rosidl_adapter 需要 em 3.x。系统 Python 3.10（`/usr/bin/python3`，当前 shell PATH 第一位）已验证 `em.BUFFERED_OPT` 存在。

**修复**：`rm -rf build install log` 清掉带污染缓存的构建目录，重新 configure 后 CMake 会找到系统 Python 3.10，rosidl 消息生成即可通过。
